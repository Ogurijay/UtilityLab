# 物品破碎工作台设计（暂不实现）

## 目标

为单个静态物体提供“选择破碎方式 → 预览 → 调整碎片 → 模拟检查 → 保存派生资产”的独立页面。

它不是人物编辑器里的一个折叠面板，也不直接修改源模型。每次破碎都保存为新的派生资产，并保留可重算的操作参数。

## 推荐入口与流程

未来只在以下位置提供 `进入破碎工作台`：

- 单物体编辑页，且当前物体至少有一个静态网格。
- 资产列表中静态模型或道具的右键菜单。

固定五步：

1. `01 选择源物体`
2. `02 设置破碎区域`
3. `03 生成碎片`
4. `04 约束与模拟`
5. `05 保存与导出`

蒙皮网格不能直接破碎。用户可以先选择一个姿势并“烘焙为静态副本”，再进入破碎工作台。

## 页面布局

### 顶部

- 返回单物体编辑
- 源资产名称与只读标识
- 撤销 / 恢复
- 重新计算
- 保存破碎项目
- 保存碎片资产
- 导出
- 后台任务状态

### 左侧

- 源物体结构
- 破碎操作栈
- 碎片列表
- 碎片分组、锁定、显隐、重命名、删除和合并
- 按体积、质量、层级或名称排序

### 中央视口

- 原始 / 破碎结果对比
- 切面、冲击点、笔刷范围和碎片边界预览
- 点击选择单个碎片，框选多个碎片
- 爆炸视图（把碎片向外分离，便于检查）
- 重力模拟、暂停、重置和慢放

### 右侧参数

按当前破碎方式显示参数，不同时展示全部工具：

- 切面：平面位置、旋转、切面材质、保留方向。
- Voronoi（泰森多边形破碎）：碎片数量、随机种子、均匀度、最小体积。
- 冲击破碎：冲击点、半径、中心密度、方向和强度。
- 笔刷破碎：笔刷半径、强度、密度；笔刷只控制碎片生成密度，不直接伪造网格裂缝。
- 方盒区域：框内破碎、框外保留或框内移除。
- 公共参数：封口、内部材质、锐边、法线、简化、碰撞体和质量。

### 底部

- 模拟播放 / 暂停 / 重置
- 当前碎片数、三角面数、非流形问题数和预计导出大小
- 任务日志与问题列表

## 首版破碎能力

### 1. 切面拆分

一次操作必须把一个组件替换为切面两侧的两个真实组件，不复制出一个仍然完整的原模型。

- 自动给切口封面。
- 切口可使用独立“内部材质”。
- 支持连续添加多个切面。
- 支持只保留一侧，但默认保留两侧。

### 2. Voronoi 破碎

根据一组种子点把封闭物体拆成多个体积碎片。

- 固定随机种子，保证保存后可复现。
- 限制最小碎片体积，避免产生大量不可用薄片。
- 支持均匀、中心密集和表面密集三种分布。

### 3. 冲击点破碎

用户在视口点击冲击点，生成中心密、外围疏的碎片。

- 冲击方向影响碎片分布。
- 强度只影响预览模拟初速度，不改变原始尺寸。

### 4. 区域笔刷

笔刷写入一张“破碎密度遮罩”，后台根据遮罩分布种子点。

- 增加、减少、平滑和清除四种笔刷。
- 支持对称。
- 每次完整笔划是一条撤销记录。

## 技术边界

### 浏览器与 Three.js

浏览器负责：

- 交互、拾取、切面与笔刷可视化。
- 低分辨率预览。
- 碎片选择、材质预览、爆炸视图和基础刚体预览。
- 展示后台任务进度与结果。

Three.js 的裁剪平面只能做显示裁剪，不能当作最终破碎结果。最终保存前必须取得真正分离、封口后的网格。

### 后端几何任务

精确网格处理交给独立后台任务：

- 首版使用 Blender 后台模式的 Python + BMesh（网格编辑模块）实现切面、封口、法线和基础清理。
- Voronoi 与高碎片量任务封装成可替换的 C/C++ 几何核心，Python 只负责任务编排。
- 每个任务记录输入哈希、参数、随机种子、日志和输出清单。
- 任务失败时保留源资产与上一次成功结果，不返回“看起来成功”的预览网格。

建议接口：

- `POST /api/jobs/fracture/preview`
- `POST /api/jobs/fracture/build`
- `GET /api/jobs/{jobId}`
- `POST /api/fracture-projects`
- `POST /api/assets/{assetId}/fracture-results`

## 数据结构

`FractureProjectV1` 至少保存：

- `sourceAssetRef`
- `sourceHash`
- `operations[]`
- `randomSeed`
- `pieceGroups[]`
- `pieceOverrides[]`
- `constraints[]`
- `simulation`
- `outputSettings`
- `lastSuccessfulJob`

每块碎片需要稳定 ID、父组件 ID、体积、质量、质心、碰撞体、可见状态和内部 / 外部材质引用。

## 约束与导出

- GLB：导出为同一场景内多个命名网格节点，并保留碎片层级和材质。
- 碎片包：GLB + `fracture.json`，保存质量、约束和冲击参数。
- Unreal：通过受控导入任务生成静态网格集合；Chaos Geometry Collection（UE 破坏集合）需要 Unreal 侧脚本或插件建立，不能声称仅靠 GLB 就完整携带。
- 源资产始终只读；“保存碎片资产”只生成派生资源。

## 验收标准

- 单切面后得到两个互补、封口、可独立选择的组件。
- 同一随机种子和参数重复计算，碎片数量与形状一致。
- 碎片没有 NaN 顶点、零面积三角形或未报告的非流形边。
- 删除、合并、分组碎片后可撤销 / 恢复。
- 保存项目再打开，操作栈和碎片覆盖信息一致。
- 导出 GLB 再载入后，碎片数量、名称、变换和材质一致。
- 超出三角面或碎片预算时先提示并降级预览，不让浏览器直接崩溃。

## 建议实施顺序

1. 切面拆分、封口、内部材质、两侧组件和 GLB 导出。
2. Voronoi 破碎与固定随机种子。
3. 碎片列表、分组、合并、碰撞体和基础模拟。
4. 冲击点与区域笔刷。
5. Unreal Chaos 导入任务。
